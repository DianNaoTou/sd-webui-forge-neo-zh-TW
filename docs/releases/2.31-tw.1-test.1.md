# 2.31-tw.1-test.1：Forge Neo 2.31 整合測試版

本版只更新 `neo-test`，以可晉級正式版的規格整合、檢查與記錄；正式 `neo` 仍為 2.30-tw.1。**尚未通過 CUDA／XPU 完整模型實機驗收，不宣稱已可直接升正式。**

## 上游與功能

- 完整合併上游 `neo` 至 `0c388f8b26d26d475c2c7104aea4eafdf7bbb3e7`；相較 Test 9 的共同基準 `f7f23149`，含 19 個上游提交、47 個檔案。
- 新增 MOSS-Image：模型辨識、推論引擎、Qwen3.5-9B 文字編碼器、Flux2 類 VAE、融合 QKV LoRA 映射與生成預設。主模型、文字編碼器、VAE 需另外取得；程式 ZIP 不含模型權重。
- 新增繁中 **JSON 構圖編輯器**：編排物件、角色與文字位置，匯入／匯出構圖 JSON，傳送至文生圖或圖生圖。它是 MOSS 專用結構提示詞工具，不代表其他模型能理解同一 JSON。
- 新增 MOSS 跳層引導（SLG）、透明度門檻、X/Y/Z 切換成本排序及兩種 VAE 切換方式；同步 CPU 量化能力判斷、GGUF 防護、混合精度記憶體估算與 VAE 注意力判斷。
- DeGrid 改為預設關閉。GGUF 整體支援在上游仍標為未完成，不能視為全面相容。

## 本輪修正與保留

- 修正上游 `ignore_start` 將字串轉成逐字元 tuple 的問題，避免把非目標權重的 missing／unexpected 訊息一併隱藏；保留多前綴支援。
- 修正 X/Y/Z「None」VAE 被當成檔名，以及比較其他 VAE 時原選 VAE 殘留；保留文字編碼器，不修改使用者全域清單。
- 插件清理失敗仍嘗試還原生成覆寫與 VAE；還原失敗仍清除暫存狀態。例外不被靜默吞掉。
- 修正 Spectrum 將變數賦值放在 assert 裡，導致 Python `-O` 移除賦值後預測崩潰；完整最佳化模式回歸納入 CI。
- 保留 `--onnxruntime-gpu` 舊版選用參數，避免上游移除後與本整合版啟動器／ONNX 修復流程不一致。一般使用者仍用既有穩定 ORT 選擇。
- 移除重複的採樣前 callback 方法覆寫，恢復設定中的插件執行順序並保留 ScriptAbortError 中止保護；SLG／ControlNet 等掛接共用此流程。
- 修正 LoRA 強度為數字時的字串判斷；保留排程語法。
- JSON 編輯器避免在頁籤不存在時報錯、重複掛載；補繁中動態標籤、錯誤訊息前綴，保留英文 JSON schema／值。載入錯誤保留對話框；修正括號往返增加反斜線、匯入時越界與尺寸驗證，保留原 JSON 的可選 tags／palette。
- 保留既有 A1111 控制項位置、ID、預設值、尺寸滑桿上限 2048、HR 自有刷新按鈕、PNG／WD14 傳送、XPU 官方環境與注意力修補。新增功能不替換既有操作區。

## 套件與更新

- 新 NVIDIA 安裝預設 Torch **2.14.0+cu130**／torchvision **0.29.0+cu130**。既有同後端 venv 沿用原版，不會因 `git pull` 自動強制更換 Torch；要切到新 CUDA 基準，關閉 WebUI 後在原啟動器的 `COMMANDLINE_ARGS` 暫加 `--reinstall-torch`，完成後移除。若另裝 Flash／xformers／Nunchaku 等二進位加速套件，必須使用與 Torch 相符的版本；未完成相容性確認前可用 `--disable-sage --disable-flash`，停用相關額外加速參數。
- Intel 繼續使用獨立官方 Torch **2.14.1+xpu**／torchvision **0.29.1+xpu**；不轉成 CUDA，不強制修改舊正式版環境。
- comfy-kitchen 升至 **0.2.40**，同步 GitPython 3.1.62、accelerate 1.15.0、tqdm 4.70.1 與上游加速套件安裝資訊。
- Gradio **4.40.0**、Pillow **10.4.0**、HEIF **0.22.0**、protobuf 與 Hub 相容約束維持。另固定 **MarkupSafe 2.1.5**：實際隔離安裝發現單獨更新核心依賴可拉入不符 Gradio 的 3.x，現由 requirements 和共用 constraints 共同保護。
- 專案 Python 仍為已採用的 **3.13.12**；未跟隨上游建議的 3.13.15 自動切換解譯器。Nunchaku 保留已驗證 wheel 矩陣與不降級 Torch 的政策，未自動改用上游第三方 Hugging Face wheel。
- 先關閉 WebUI，在 `neo-test` 目錄執行 `git pull --ff-only`。含 Git 的舊 Test 8／9 ZIP 可直接更新；GitHub Source code ZIP 不含 `.git`。不可把 ZIP 直接覆蓋既有安裝。
- CI 通過後由既有流程建立固定 **neo-test.zip** 與 SHA-256，包含 Git 更新資訊；保留舊固定測試版，不變更正式 Latest。

## 驗證與發布門檻

本機：完整 CPU 回歸、Python `-O`、Node 前端事件與 JSON 往返、編譯、未定義名稱檢查；Windows Python 3.13 的 CUDA／XPU 主套件、ADetailer、WD14、preprocessor 依賴解析。具體結果與限制記錄於 [整合審查](../reviews/2026-10-25-forge-231.md)。

CI 對 Linux 執行完整回歸及新數值路徑，Windows 執行新 2.31 CPU 回歸、檔案共享／設定／XPU 隔離／Git ZIP 測試，通過後才發布測試 ZIP。CI 成功不代表 GPU 生成驗收。

正式版前仍需兩台實機：

1. RTX 5060 Ti 與 B580 分別測 SDXL／Illustrious 一般生成、連續生成、Hires 開關與中斷後再生成，記錄版本、峰值記憶體、耗時、NaN／OOM／DEVICE_LOST。
2. MOSS 實際權重載入、正負提示詞、SLG 開關／區間、LoRA、JSON 文字與位置；核對下載來源、模型組合與品質。小尺寸隨機 CPU 計算不驗證真實權重品質。
3. LayerDiffuse 透明 PNG 的 alpha 門檻 0／16、半透明邊緣、連續啟用／停用與模型切換；ADetailer 同開的既有限制維持。
4. X/Y/Z 比較主模型、None／兩個 VAE、保留文字編碼器；完成或出錯後確認原設定還原。分別測一般 VAE 與僅權重 VAE 軸。
5. JSON 編輯器拖曳／縮放、儲存／載入、兩頁傳送；原介面布局、插件按鈕與官方 XPU 的獨立快取／輸出。

本版不宣稱修復既有 B580 OOM／DEVICE_LOST，也不宣稱 MOSS 在 12GB／16GB 顯存一定可用。
