# 2.31-tw.1-test.4：Intel WD14 GPU 加速選用測試版

只更新 `neo-test`，延續 Test 3 全部功能與翻譯修正。正式 `neo` 維持 2.30-tw.1；本次不升正式。尚未在 B580 上執行 GPU 驗收，不保證每個模型可用或一定更快。

## 兩個 Intel 啟動檔

| 啟動檔 | WD14 辨識後端 |
|---|---|
| `webui-user-intel-arc.bat` | 原始模式，沿用 CPU ONNX Runtime |
| `webui-user-intel-arc-wd14-gpu.bat` | 嘗試以獨立 OpenVINO worker 使用 Intel GPU，失敗退回 CPU |

兩者仍使用既有官方 XPU 生圖 profile、同一份 XPU 設定與模型快取、同一個 7862 埠，請先關閉前一個 WebUI 再切換。新啟動檔只改變 WD14 ONNX 辨識後端，不是另一套生圖核心；NVIDIA 啟動方式不變。本版沒有新增先前討論的剪貼簿匯入按鈕。

## 使用方式

1. 關閉 WebUI，更新測試分支或下載本版 Release 附件 `neo-test.zip`。原有個人啟動參數請沿用，不要覆蓋個人模型或設定。
2. 執行 `webui-user-intel-arc-wd14-gpu.bat`。首次會在專案的 `runtime/wd14-openvino/venv` 建立獨立小環境，安裝固定 OpenVINO **2026.3.1** 與 numpy **2.3.5**；不向生圖 venv 安裝 OpenVINO，也不更換其中的 Torch、ORT 或 CUDA 套件。下載／安裝失敗會提示並以 CPU 辨識繼續啟動。
3. 在 WD1.4 標籤器選一個既有 ONNX 模型，或 PixAI／Camie，按「辨識」。原有模型下載策略不變；PixAI／Camie 仍是首次辨識才下載。大型模型首次 GPU 編譯可能需要數分鐘，之後使用獨立編譯快取。
4. 看終端是否出現 `[WD14 GPU] OpenVINO GPU worker: GPU...` 與實際裝置名稱。選用 GPU 啟動檔或成功安裝套件不代表模型已在 GPU 執行；若顯示 `OpenVINO failed; using CPU ONNX Runtime`，就是已退回 CPU，旁邊會保留失敗原因。
5. 比較完成後關閉 WebUI，改回原始 Intel 啟動檔即可回到 CPU 辨識；無須卸載環境或重新安裝生圖套件。原始啟動檔會清除 GPU opt-in 旗標。

自動選擇唯一獨顯；若有多張 GPU 無法明確判定，會提示並退回 CPU，可在命令列指定：

```bat
webui-user-intel-arc-wd14-gpu.bat --wd14-device GPU.0
```

`GPU.0` 不保證就是 B580；應依裝置清單與實際名稱選擇。保留原啟動檔可用的生圖參數。顯式 `--additional-device-ids cpu:0`（若使用此後端參數）優先於 GPU 模式。

## 範圍與退回機制

- 共用 ONNX session 介面，原有 WD14 的 NHWC／BGR 前處理、PixAI／Camie 的 NCHW 前處理、輸出名稱、標籤分類、信心度與傳送功能均沿用；不將 TensorFlow／DeepDanbooru 模型改成 OpenVINO。
- GPU worker 使用固定 float32 推論提示，不使用 AUTO／HETERO 的隱式 CPU 混合執行。檢查實際 execution devices；不把 CPU 計算印成 GPU 成功。GPU 與 CPU 浮點結果仍可能略有差異，尤其是臨界信心度的標籤。
- GPU 初始化、模型編譯或推論失敗時，關閉 worker 並使用原模型的 CPU ORT 重試；之後該 session 留在 CPU，避免每張圖片重複嘗試失敗的 GPU。卸載再載入可重新嘗試。CPU 也失敗時沿用既有錯誤處理，不偽造成功結果。
- 初始化最多等待 600 秒，單次推論最多 120 秒，逾時會關閉 worker 並嘗試 CPU。模型卸載／正常程式退出會清理 worker 和暫存影像張量；不複製模型權重。編譯快取與執行環境留在 `runtime/wd14-openvino` 供下次使用。
- WD14 GPU 與生圖共用 B580 的實體顯存與驅動；程序隔離保護套件相容性，不能保證硬體 DEVICE_LOST 不影響其他 GPU 工作。需要生圖時可使用標籤器既有的卸載選項釋放模型。
- 獨立環境與編譯快取需要額外磁碟空間。沒有修改顯示卡驅動、不宣稱修復既有 B580 生圖 OOM／DEVICE_LOST。

## 驗證與實機比較

本機一般／最佳化完整 WebUI 回歸各執行 205 項（其中 2 項需要獨立 OpenVINO 環境，另行執行）；獨立環境的 13 項 worker 回歸一般／最佳化均通過，既有 WD14 16 項與 Node 19 項通過。以真實 OpenVINO CPU plugin 和 ORT CPU 跑小型 ONNX 模型，核對輸出順序與數值，另測獨立程序傳輸、目前輸入不沿用上一筆、GPU 失敗 CPU 退回、逾時終止、模型卸載與環境隔離。Windows Python 3.13 套件解析確認有相容 wheel。

CI 在 Windows／Linux 安裝實際固定 OpenVINO、ONNX 與 ORT，執行 worker 一般／最佳化回歸；主 WebUI 回歸維持原有環境，全部通過才打包。CPU CI 和模擬 worker 都不等於 B580 GPU 測試。

B580 請用同一張圖片、同一模型與信心度，分別測原始／GPU 啟動檔，記錄首次編譯與第二次辨識時間、GPU 成功或 CPU 退回訊息、模型名稱、顯存占用，並確認辨識後還能正常生圖。可先測一般 WD ONNX，再測 PixAI、Camie；失敗時提供 `[WD14 GPU]` 的錯誤訊息即可，不需要提供圖片或敏感提示詞內容。
