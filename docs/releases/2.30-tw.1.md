# 2.30-tw.1 繁中整合版

發布日期：2026-10-13

將已測試的 `neo-test` 升為正式版，版本顯示 `neo 2.30-tw.1`。相較上一正式版 `2.29.2-tw.1`，包含以下更新與修正。

## 新增與上游更新

- 以 Forge Neo 2.30（`ce6848b8`）為基礎，另納入上游 `58700b99` 的 VAE 通道修正；並非同步所有上游最新提交。
- 新增 **Qwen-Image-2.1** 支援：模型辨識、文字編碼器、VAE、參考圖片／編輯模式及預覽解碼。主模型、文字編碼器與 VAE 需另外下載，程式 ZIP 不含模型；下載與模型組合依 [上游說明](https://github.com/Haoming02/sd-webui-forge-classic/tree/ce6848b8) 為準。
- 新增 **DeGrid** 後處理，可在「附加功能」減輕格紋；這不是圖片放大模型。
- 新增正向／反向條件批次計算選項（Batch Cond/Uncond）；可能加快生成，但會增加顯存用量。
- 新增 VAE／文字編碼器下拉選單的檔名顯示方式設定。
- 調整 SDPA／VAE 注意力分塊、VAE 精度選擇、Anima LLLite 映射與相關模型載入相容性。
- 改善透明圖片保存及批次提示詞輸出資訊，補齊負向提示詞、Seed、Subseed 等生成紀錄。

## Bug 修正與繁中整合

- **修正 NVIDIA 誤裝 CPU-only PyTorch**：移除共用依賴中的裸 `torch`；啟動時檢查 CUDA 後端並自動重裝錯誤套件。這包含先前 RTX 4070 回報的修補，現正式收錄。
- **補強 Intel Arc 後端防護**：同樣檢查 XPU 套件；重裝後仍不是預期後端就停止啟動，避免靜默退回 CPU。
- 透過共用 `run_pip()` 安裝插件時，約束已安裝的 torch／torchvision 版本，降低被替換成 CPU 版的機率。要求衝突版本的插件可能安裝失敗；自行呼叫 pip 的插件不受此防護涵蓋。
- **修正 DeGrid 寫死 CUDA**：使用 Forge 偵測到的裝置，GPU 處理失敗時嘗試 CPU，避免 Intel Arc 的附加功能直接因 CUDA 呼叫出錯。
- **修正 Qwen 2.1 分塊 VAE 四通道配置不相容**：2D 分塊解碼的三種方向均使用實際輸出通道數，保留既有 RGB 路徑。
- **修正 Flash Attention 遮罩保護**：有明確遮罩時保留原始遮罩走 SDPA，避免 Python `-O` 移除 `assert` 後忽略遮罩。未納入上游 `ede60e1a` 的 causal Flash 加速；原因見 [技術審查](../reviews/2026-10-11-vae-flash.md)。
- 補齊 DeGrid、Qwen 2.1 參考圖片、批次條件計算、VAE／文字編碼器選單等繁體中文；修正提示詞延遲設定的說明翻譯未生效。
- 保留原有 Intel XPU Math SDPA／查詢分塊、None／Ignore 提示詞權重修正、Gradio 4.40／Pillow 10.4.0 相依組合及常用插件整合。

## 驗證與已知限制

- 維護者回報本輪測試已足夠，決定正式發布；這不等於所有模型、插件、Windows 全新安裝及硬體組合都已驗證。
- 發布前以隔離的 Linux／Python 3.12／PyTorch 2.14.1+cpu 執行完整回歸 60/60 通過、0 跳過；Python `-O` 的 5 項 VAE／Flash 回歸亦通過，compileall 與空白檢查通過。CPU 數值測試不代表 CUDA／XPU kernel 實機驗證。自動檢查結果見本版 PR／Actions 與共同工作日誌。
- **Intel Arc B580 12GB 仍有已知問題，這次未修復**：2026-10-13 紀錄確認一般生成多次完成；一次兩階段生成完成後，下一次提示詞處理出現 `OUT_OF_DEVICE_MEMORY`，清理時出現 `DEVICE_LOST`。根因未確認；不能據此斷言是記憶體洩漏、硬體故障或本版新增回歸。
- B580 高解析度修復仍可能較慢、OOM 或裝置失聯。遇到該錯誤先完全關閉 WebUI 再重開；不保證重啟即可避免復發。暫不阻擋本次發布，後續依回報另行修補。
- Qwen-Image-2.1 與各種量化／模型組合的生成品質、顯存需求與效能，仍以實際模型和設定為準；本輪自動測試未載入真實模型權重。
