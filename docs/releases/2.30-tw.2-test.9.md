# 2.30-tw.2-test.9：LayerDiffuse 繁中測試整合

只更新 neo-test，正式 neo 不變。新增 LayerDiffuse 可選功能，預設關閉；由獨立插件資料夾提供，不修改核心 Python 推論程式。沿用 Test 8 的 ZIP Git 更新機制。

## 更新與使用

先關閉 WebUI，在 neo-test 專案目錄執行 `git pull`。若已安裝其他 LayerDiffuse，請先停用舊版再重新啟動；本插件不能與另一份同名腳本同時載入。
文生圖／圖生圖可展開「LayerDiffuse 圖層透明生成」。先使用 SDXL、批次 1、Attention 注入，關閉 ADetailer 及 Hires，輸出選 PNG。首次啟用才下載對應權重，未啟用不建立權重目錄或下載權重。

固定 Test 9 ZIP 由既有 Linux／Windows CI 全部通過後建立 Prerelease；若尚未出現，使用 neo-test Git 分支。舊 Test 8 ZIP 是固定舊快照，需 git pull 才取得本次功能；不覆蓋既有固定版附件或正式 Latest。

## 修改

- 介面與選項繁中化，保留英文 API／圖片資訊方法值。
- LoRA 使用目前 Forge Neo WeightAdapter；檢查權重格式、模型鍵、擴通道形狀與實際套用結果。
- SDXL 合成條件由插件自己的 conditioning modifier 注入、對齊批次，不改全域 is_inpaint。
- 透明 VAE 快取依請求、SD1.5／SDXL、編碼／解碼區分；透過現有 cleanup_processing finally 介面清理，涵蓋成功與失敗。
- 新增模型、RGBA 圖片、批次及 API 檢查。SD1.5 權重只支援 1；暫時拒絕 ADetailer 同時啟用，以及 SD1.5 的其他 Attention 掛接。
- 官方權重固定 revision、SHA-256 與 size，保留既有不符檔案並停止。未新增安裝器、套件依賴、模型本體或第三方 Git／快取。

## 已驗證與未驗證

本機新增 16 項 CPU 回歸通過，涵蓋實際插件 helper／AST 擷取的 production 函式：條件注入、CFG=1、batch 擴展、停止比例分支、adapter 格式與缺鍵、依模型家族分開快取、重複清理與清理失敗、ADetailer／模式保護、下載完整性驗證及保留損壞原檔。Python 編譯檢查通過。測試使用 CPU 陣列／mock，不執行模型生成，不代表完整 Forge 啟動成功。

CI 另跑既有完整回歸；結果以 GitHub Actions 為準。CUDA／XPU 生成、實際 Gradio 介面、透明品質與效能未在此環境驗證。

## 實機驗收順序

1. RTX 5060 Ti：SDXL 透明圖 → 連續兩次 → 停用後一般生成，確認狀態未殘留。
2. 同一 WebUI 工作階段切換 SD1.5／SDXL；再測 Illustrious 的輪廓、半透明邊緣與風格。
3. SDXL 四種合成方法、batch 1／2、停止比例 1／0.5；CFG 1 與一般 CFG。
4. Hires 開關、同模型放大、跨家族 Hires 模型應明確拒絕；中斷與失敗後再次一般生成。
5. SD1.5 batch 2／3 相應方法；錯誤批次、缺圖片、ADetailer 同開、其他 Attention 掛接應顯示提示並停止。
6. Intel B580 官方 XPU：重複以上基本流程，記錄 NaN、OOM、DEVICE_LOST、峰值記憶體與耗時；不宣稱已修復既有 XPU 問題。

原有使用者設定、模型、輸出與 CUDA／XPU 環境版本均不變。插件由主專案 Git 管理；長期不使用請在擴充功能頁停用，避免直接刪除受追蹤檔案導致更新衝突。
