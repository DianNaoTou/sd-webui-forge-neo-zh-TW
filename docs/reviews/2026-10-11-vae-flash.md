# VAE 與 Flash Attention 審查（ChatGPT，2026-10-11）

本輪 PR 以 `neo-test` 的 `7619c3174e760a18b4b52c44fb87b629e55fd598` 為基準，維持 `2.30-tw.1-test`；正式 `neo` 為 `7008f298b9c113a954bbdba92859ad82d50ab68b`／`2.29.2-tw.1`。測試分支領先正式版 21 個提交、落後 0；上游 `neo` 為 `ede60e1aefd30ce0f7341c8ff538f48e0fd047c9`，尚缺下列兩項修補。正式 requirements 仍含裸 `torch`，測試分支已有後端防護。本輪不合併、不發布。

## 已納入：VAE `58700b99`

2D tiled decode 三種 tile 方向均傳入 `out_channels=self.output_channels`。`tiled_scale_multidim` 預設配置 3 通道，但 Qwen 2.1 VAE 設定為 4；未傳入會在結果配置／累加時不相容。保留 RGB 3 通道與既有 3D 路徑。

回歸測試擷取實際 production 函式，執行 PyTorch CPU tiled decode；涵蓋 3／4 通道、單塊／重疊分塊、非方形輸入、batch=2、三種 tile 方向及數值等價。使用合成 decoder，未載入真實 VAE 權重。

## 待審：Flash 優化 `ede60e1a`

本輪未 cherry-pick 此提交；Qwen dispatcher 保持原版。原始 explicit mask 繼續走 SDPA，未啟用 Qwen causal Flash 加速。

- Qwen `build_sequence` 的文字片段：起點 `start=L`、長度 `n`，Query 長度 `n`、Key 長度 `L+n`；mask 為 `ones(n,L+n).tril(L)`，允許 key column `j <= row i + L`。圖像片段 mask=None，可讀該片段及其前綴。
- FlashAttention **2.1 起** causal 使用右下對齊：`j <= i + key_length - query_length`，對現有 Qwen 文字遮罩等價；**2.0** 使用左上對齊，非方形片段不等價。正式來源：[FlashAttention README / 2.1](https://github.com/Dao-AILab/flash-attention#21-change-behavior-of-causal-flag)。本輪閱讀當時 main，未將浮動文件當作實際安裝版本證據。
- 上游 `causal=mask is not None` 只是有無 mask 判斷；`assert mask is None or causal` 不驗證 mask 內容。若有 padding、additive bias、局部遮罩或擴充功能提供的自訂限制，直接省略原始 mask 會改變運算。這是由程式分支確認的語意風險；未觀察到現有標準 Qwen builder 自行產生 padding mask。
- `flash_enabled()` 目前只判斷 NVIDIA GPU 與套件可匯入，未限制 FlashAttention >=2.1。不能保證所有可安裝版本的非方形語意。
- SDPA 原路徑使用 `attn_mask=mask, is_causal=False`，保留 offset causal 的原始內容；不能改成 `is_causal=True`，PyTorch 非方形普通 causal 為左上對齊。

本輪另修正既有保護：以明確分支取代 `assert mask is None`，避免 Python `-O` 移除 assert 後丟棄遮罩。正常遮罩 fallback 不再記錄預期內的 assert 錯誤；無遮罩 Flash 呼叫及 kernel 失敗 fallback 保留。XPU 不選用 Flash；VAE 修改為共用、無裝置硬編碼。

數值測試涵蓋實際 Qwen segments、非方形對齊差異、bool／padding／additive／broadcast masks、`causal=True` 提示、Python optimize=1、head-shaped 輸入輸出、無 mask 路徑及模擬 Flash kernel 失敗。Flash kernel 是 CPU 替身，不能代表 CUDA kernel 驗證。

未來若納入 Flash causal 優化，需確認套件版本及 mask 等價性、保留任意遮罩 fallback，並測量檢查成本（逐層 GPU mask 比較／host 同步可能影響效能）。目前選擇保持正確性，避免未驗證的優化。

## 驗證界線

本輪以 Linux／Python 3.12／PyTorch 2.14.1+cpu 執行；CPU torch 僅裝在隔離測試目錄，未修改專案依賴。沒有 CUDA／XPU 裝置、Windows、模型權重或 WebUI 完整啟動。既有 XPU Math SDPA、emphasis、後端防護、語系等 tests 一併執行；數值測試不能替代 RTX 5060 Ti／Arc B580 的實機生成與長時間穩定性驗證。B580 歷史 OUT_OF_RESOURCES／DEVICE_LOST 不列為本輪新回歸。

實際本機結果：完整 unittest **60/60 通過、0 跳過**，包含原有 5 項 XPU Math SDPA 數值測試與 emphasis tensor 測試；新增 5 項回歸在正常及 `python -O` 模式通過。compileall 與 diff whitespace 檢查通過。以原始 `7619c317` production code 做負控制，捕獲 2 組四通道配置錯誤與 5 組 optimize=1 遮罩數值差異。初次全套測試曾因測試環境缺 tqdm 及原有空白路徑測試假設未安裝 torch 而失敗；補齊隔離測試依賴，並使該測試明確覆蓋有／無 torch pins 後全套通過，沒有更動依賴政策實作。

PR 加入唯讀權限的 GitHub Actions CPU regressions：完整 unittest、compileall、`-O` 遮罩測試；CI 狀態以 PR 的實際執行紀錄為準，不能用本機通過代替。
